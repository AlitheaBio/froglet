# Froglet plugin qualification with standalone NVIDIA OpenShell

This is a reproducible **plugin/runtime boundary test**. It imports the actual
OpenClaw plugin, registers its `froglet` tool, and executes two real HTTP-backed
actions inside OpenShell against a disposable Froglet node. It does not run an
OpenClaw gateway, a language model, a scientific workload, or managed NemoClaw
onboarding.

The observed platform is Apple Silicon macOS with Docker Desktop, OpenShell
**0.1.7**, Node **22.14.0** inside the workload, and Froglet built from public
commit `c6c5dc53f38a2c485f95cd6776f32f4e7b33785b`. The supplied preparation helper
deliberately rejects other host platforms; Linux is not yet verified by this
recipe.

## What the check establishes

1. Under an explicit baseline policy, `list_local_services` and
   `get_spend_status` both succeed against the same test node.
2. After removing only the spend-read rule and waiting for the policy to load,
   service listing still succeeds. The identical spend read receives an
   OpenShell HTTP 403 `policy_denied` response.
3. OpenShell records an L7 REST denial. The HTTPS adapter's access log records
   no corresponding request reaching Froglet after the policy change.

The workload is non-root. Its policy requires Landlock enforcement, disables
operator-requested host bind mounts, and grants `/usr/local/bin/node` only the specified HTTPS
endpoint and REST paths. Gateway authentication uses mTLS. Endpoint and
interception certificates remain verified. A separate test CA signs a server
leaf certificate; this is the certificate arrangement qualified here.

The two Froglet bearer tokens are generated by the disposable local node and
copied into the workload. **The plugin can read them.** This test does not
implement OpenShell credential substitution, establish secret invisibility, or
test protection against inference from permitted responses.

## Version boundary

Standalone OpenShell and NemoClaw must be qualified separately. As checked on
2026-11-09, maintained NemoClaw **v0.0.142** pins OpenShell **0.0.116**, while this
test uses standalone OpenShell **0.1.7**. Do not describe this result as a full
NemoClaw deployment. The existing NemoClaw adapter profile and doctor remain
useful setup components; managed onboarding and agent inference are not yet
verified here.

## Prerequisites and pinned tools

Use a fresh terminal on Apple Silicon macOS. Start the existing Docker Desktop
installation and confirm `docker info` succeeds. Build Froglet from the revision
being qualified, for example `cargo build --locked --release --bin froglet-node`.
Python 3.10 or later and OpenSSL must be on PATH. No model download, inference
provider, paid API, production token, or production data is needed.

From this repository's root, install the official binaries into a temporary
directory. The digests below are the published v0.1.7 macOS arm64 release hashes:

```sh
repo_root="$PWD"
task_dir=$(mktemp -d "${TMPDIR:-/tmp}/froglet-openshell.XXXXXX")
mkdir "$task_dir/bin"
curl -fLsS https://github.com/NVIDIA/OpenShell/releases/download/v0.1.7/openshell-aarch64-apple-darwin.tar.gz -o "$task_dir/cli.tar.gz"
curl -fLsS https://github.com/NVIDIA/OpenShell/releases/download/v0.1.7/openshell-gateway-aarch64-apple-darwin.tar.gz -o "$task_dir/gateway.tar.gz"
printf '%s  %s\n' c5899a2fe6b40c371e7d660bd8983cefb766d04658bd9193b12a80525b12c742 "$task_dir/cli.tar.gz" | shasum -a 256 -c -
printf '%s  %s\n' fe47a385c16c10cde8905bf1bf627e4a9fbf4a81bcf44b388dec4d22618fbb48 "$task_dir/gateway.tar.gz" | shasum -a 256 -c -
tar -xzf "$task_dir/cli.tar.gz" -C "$task_dir/bin"
tar -xzf "$task_dir/gateway.tar.gz" -C "$task_dir/bin"
export PATH="$task_dir/bin:$PATH"
```

Check each command succeeds before continuing. This leaves Homebrew services and
ordinary OpenShell configuration untouched. Ports 18670 and 19443 must be free;
the recipe does not stop an existing service occupying either port.

## Prepare the real local backend and gateway

The helper generates private task-only certificates, writes the gateway and
policy configuration, starts a real Froglet node with payments disabled, and
exposes a loopback HTTPS adapter. The adapter forwards GET requests to that node
and records only method, path, and upstream status; it does not mock API results.

```sh
python3 integrations/openclaw/froglet/scripts/openshell-qualification-backend.py \
  --work-dir "$task_dir" --repo "$repo_root" \
  --binary "$repo_root/target/release/froglet-node" \
  > "$task_dir/backend.log" 2>&1 &
backend_pid=$!
```

Wait for `$task_dir/ready.json` and check the helper is still running. If it exits,
inspect `backend.log` and stop; do not continue with partial setup.

```sh
. "$task_dir/env.sh"
openshell-gateway --config "$task_dir/config/gateway.toml" \
  > "$task_dir/gateway.log" 2>&1 &
gateway_pid=$!
openshell gateway add https://127.0.0.1:18670 --local --name froglet-qualification
openshell status
```

Wait until status reports **Connected**, authenticated with mTLS, version
**0.1.7**. A successful `gateway add` alone does not establish connectivity.

## Run the baseline and denial checks

```sh
docker build -t froglet-openshell-qualification:node22.14.0 "$task_dir/image"
openshell sandbox create --name froglet-qual \
  --from froglet-openshell-qualification:node22.14.0 \
  --policy "$task_dir/config/policy-baseline.yaml" \
  --no-auto-providers --detach -- /bin/sleep infinity
openshell sandbox get froglet-qual --output json > "$task_dir/evidence/baseline-state.json"
```

Require phase `Ready` and `configuration_admission.state` equal to `accepted`.
For directory uploads, the destination is the **parent** directory: OpenShell
retains the source basename. Single-file token uploads name the final file.

```sh
openshell sandbox upload froglet-qual "$repo_root/integrations/openclaw/froglet" /sandbox/froglet/integrations/openclaw
openshell sandbox upload froglet-qual "$repo_root/integrations/shared/froglet-lib" /sandbox/froglet/integrations/shared
openshell sandbox upload froglet-qual "$task_dir/stage/provider.token" /sandbox/provider.token
openshell sandbox upload froglet-qual "$task_dir/stage/runtime.token" /sandbox/runtime.token
openshell sandbox exec froglet-qual --no-login-shell -- node \
  /sandbox/froglet/integrations/openclaw/froglet/scripts/qualify-openshell-plugin.mjs baseline \
  > "$task_dir/evidence/baseline.json"
openshell policy set froglet-qual --policy "$task_dir/config/policy-restricted.yaml"
openshell policy list froglet-qual
openshell sandbox get froglet-qual --output json > "$task_dir/evidence/restricted-state.json"
```

Wait for the new policy to show `Loaded`. Require its configuration admission to
be `accepted`, and verify the active policy contains only the service-listing
REST rule. A pending revision is not evidence that the restriction is active.

```sh
openshell sandbox exec froglet-qual --no-login-shell -- node \
  /sandbox/froglet/integrations/openclaw/froglet/scripts/qualify-openshell-plugin.mjs restricted \
  > "$task_dir/evidence/restricted.json"
openshell logs froglet-qual -n 500 > "$task_dir/evidence/openshell.log"
```

The probe exits nonzero on any unexpected outcome. It requires both baseline
reads to succeed, the restricted listing to succeed, and the restricted spend
read to include both `403` and `policy_denied`. Also inspect the independent
evidence:

- `openshell.log` must contain `DENIED GET` for `/v1/runtime/spend` with `engine:l7`.
  Log delivery can lag; collect it again if the event has not arrived yet.
- `backend-access.jsonl` must contain two successful service-listing requests and
  only one spend request, from the baseline. An extra request from a separate
  diagnostic must be identified rather than silently counted as a test result.
- Preserve the source revision, CLI versions, accepted policies, and image
  digests with the result. Retain failed attempts as diagnostics rather than
  presenting them as successful qualification runs.

## Cleanup and evidence handling

After saving the nonsecret evidence, delete only this test's workload, then stop
the two processes started above. The helper stops its disposable Froglet child.

```sh
openshell sandbox delete froglet-qual
kill "$gateway_pid" "$backend_pid"
wait "$gateway_pid" "$backend_pid" 2>/dev/null || true
```

The task directory contains private test keys and token files. Publish selected
files from `evidence/`, not the entire directory. Remove the private task
directory after retaining the needed evidence. Docker caches remain available;
do not prune unrelated images, volumes, or containers to clean up this test.

The result is limited to the named plugin actions and policy on the tested
platform. It does not establish universal rollback, privacy of allowed model
updates, scientific validity, GPU acceleration, or customer deployment.
